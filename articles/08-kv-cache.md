# 08｜KV Cache：推理时为什么能省计算

> 阅读目标：理解自回归生成时每一步到底在重复计算什么；掌握 KV Cache 缓存的内容、更新规则与 prefill/decode 两阶段；能从计算图上严格论证"缓存输出与重算逐位一致"；会估算 KV Cache 省掉的计算量与付出的内存代价。
>
> 前置知识：第 02 篇缩放点积注意力公式；第 04 篇因果 mask 与自回归生成（训练并行 vs 生成串行）；第 06 篇 Transformer block 的内部结构（注意力 + FFN 的计算量分布）；第 07 篇 Decoder 生成流程。

第 07 篇结尾埋了个伏笔：Decoder 生成时，Encoder 只算一次、每一步复用——因为源语言的表示不随生成推进而改变。KV Cache 把同一个"复用"思想推到了极致：**连 Decoder 自己过去算出的 K、V 也不重算了**。这一篇先把"每一步到底在重复算什么"算清楚，再证明缓存是精确的、不是近似的，最后算清它省了多少、又花了多少。

> 结论性质声明：本篇中"缓存输出与重算逐位一致""每步计算量从 $O(t \cdot d^2)$ 降到 $O(d^2 + t \cdot d)$""KV Cache 内存占用公式"是**严格推导**；"prefill/decode 两阶段的工程划分""decode 是 memory-bound"是**工程实践**的描述；"某种缓存驱逐策略好不好"是**需实验验证**的结论，文中逐一标注。

## 1. 问题：生成时每一步都在重复算什么？

**直觉。** 自回归生成第 $t$ 个词时，一个天真的实现是：把整个前缀 $[x_1, \dots, x_t]$ 重新过一遍模型，取最后一个位置的输出。但第 $t-1$ 步刚刚才算过 $[x_1, \dots, x_{t-1}]$——这 $t-1$ 个位置的表示，这一步又原样算了一遍。生成 100 个词，第 1 个词被算了 100 遍，第 2 个词被算了 99 遍……纯粹的重复劳动。

**严格表述。** 记朴素实现的第 $t$ 步为一次完整前向，输入长度为 $t$。生成 $T$ 个词共做 $T$ 次前向，输入长度分别为 $1, 2, \dots, T$。问题是：第 $t$ 步的前向里，**前 $t-1$ 个位置的结果是否和第 $t-1$ 步算出来的一模一样**？如果一样，重复计算就是浪费；KV Cache 就是把这部分浪费砍掉。

## 2. 关键观察：在因果 mask 下，过去算出的东西不会变

**直觉。** 因果 mask 保证"信息只从过去流向未来"：位置 $i$ 的表示只依赖位置 $\le i$。新长出来的第 $t$ 个词，不可能反过来改变第 $i < t$ 个词已经算好的表示。所以第 $t$ 步重算前缀时，前 $t-1$ 个位置的结果注定和上一步相同——算了也白算。

**严格论证（本篇第一个核心结论：缓存精确性的数学基础）。** 对第 $l$ 层、位置 $i$ 的隐状态 $h_i^{(l)}$ 做关于层数 $l$ 的归纳：

- 基础：$h_i^{(0)}$ 是 token $i$ 的嵌入 + 位置编码，只与 $i$ 自身有关，与第几步算的无关；
- 归纳：因果 mask 下，$h_i^{(l)}$ 只依赖 $\{h_j^{(l-1)} : j \le i\}$。若对 $l-1$ 层结论成立，则第 $t$ 步（$t > i$）重算时，所有依赖项与第 $i$ 步算出的完全相同，故 $h_i^{(l)}$ 不变。

于是每层的 $K_i^{(l)} = h_i^{(l)} W_K^{(l)}$、$V_i^{(l)} = h_i^{(l)} W_V^{(l)}$ 在第 $t$ 步重算时也**逐位不变**（严格成立，条件：推理时无 dropout 等随机性——推理本就关闭这些）。第 $t$ 步真正新的计算只有三样：

1. 新 token 的 $q_t, k_t, v_t$ 投影；
2. $q_t$ 对**全部** $K_{1..t}$ 的注意力打分与加权（$K$、$V$ 里旧的部分直接复用）；
3. 新 token 过 FFN。

**结论（严格）：** 缓存过去的 K、V 并复用，输出与"每步完整重算"**逐位一致**——这是精确的 memoization，不是近似。近似方法（如稀疏注意力）会改变结果，KV Cache 不会。

## 3. KV Cache：缓存什么、怎么更新

**直觉。** 每一步算完，把新 token 的 $k_t, v_t$ 追加到缓存里；下一步算注意力时，$K = [\text{缓存的 } K_{1..t-1}; k_t]$，$V$ 同理。缓存只增不改——第 2 节已证明旧条目永远不会变。

**严格规则。**

- **缓存内容**：每一层、过去所有位置的 $K$ 和 $V$。$Q$ 不进缓存——每步只有一个新的 $q_t$，没有复用价值；
- **更新规则**：append only。条件：必须配合因果 mask；若用双向注意力（Encoder），"过去不变"的论证失效，朴素 KV Cache 不再精确；
- **两阶段流程**（工程实践的描述）：
  - **prefill**：prompt 一次完整前向，填满全部 $K$、$V$ 缓存；
  - **decode**：每步只把**一个新 token**过模型，查缓存、算新 $q_t$、append 新 $k_t, v_t$。

~~~mermaid
flowchart TB
    P["prompt tokens x_{1..n}"] --> PF["prefill：一次完整前向"]
    PF --> C["KV Cache：每层 K_{1..n}, V_{1..n}"]
    C --> D["decode 第 t 步：只输入新 token x_t"]
    D --> Q["算 q_t, k_t, v_t；q_t 对缓存 K 打分"]
    Q --> O["输出 y_t；append k_t, v_t 进缓存"]
    O --> C
~~~

注意第 07 篇的结论在这里是特例：交叉注意力的 $K$、$V$ 来自 Encoder 输出 $Z$，生成全程不变——相当于一份"永不追加"的 KV Cache，prefill 一次、decode 纯复用。

## 4. 严格推导：到底省掉了多少计算？

**直觉。** 省掉的是"对整个前缀重做投影和 FFN"——而这恰恰是 Transformer 里最贵的部分（第 06 篇：FFN 占一层参数的 $2/3$）。

**严格计数。** 约定：一次 $d \times d$ 矩阵乘向量计 $2d^2$ flops（乘加各一次）；只看单头、单层，忽略 softmax 常数与 LayerNorm。记第 $t$ 个 decode 步：

| 部分 | 无缓存（前向长度 $t$） | 有缓存（只算新 token） |
|---|---|---|
| Q/K/V/输出投影 | $8t \cdot d^2$ | $8d^2$ |
| 注意力 $QK^\top$ + 加权 | $4t^2 \cdot d$ | $4t \cdot d$ |
| FFN（$d \to 4d \to d$） | $32t \cdot d^2$ | $32d^2$ |
| **合计** | $40t \cdot d^2 + 4t^2 \cdot d$ | $40d^2 + 4t \cdot d$ |

对 $t = 1 \dots T$ 求和（decode 阶段，prefill 两边相同不计入）：

```math
\begin{aligned}
\text{无缓存} &\approx 20T^2 d^2 + \tfrac{4}{3}T^3 d \\
\text{有缓存} &\approx 32T d^2 + 2T^2 d
\end{aligned}
```

**解读（严格推导 + 条件）。** 实际中 $d \gg T$（如 $d = 4096$，$T$ 几百到几千），$d^2$ 项主导，加速比约为 $\frac{20T^2}{32T} = \frac{5T}{8}$。取 $T = 100$：约 **60 倍**。条件有二：(1) $d \gg T$ 使 $T^3 d$ 项可忽略（$T$ 接近 $d$ 时加速比会打折）；(2) 这是 decode 阶段的比较，prefill 成本两边一样。

**代价：内存换计算（严格公式）。** KV Cache 大小 = $2$（K 和 V）$\times N$（层数）$\times T$（长度）$\times d$ 个元素。取 $N = 32$、$d = 4096$、$T = 2048$、fp16：

```math
2 \times 32 \times 2048 \times 4096 = 536{,}870{,}912 \text{ 个元素} \approx 1.07\,\text{GB}
```

"KV Cache 让推理变快"是严格结论；"1 GB 算不算贵"是工程判断——在长上下文推理里，KV Cache 往往是比权重更大的显存占用，这也是第 09 篇要讲 GQA/MQA 的动机。

**数值示例。** 取 $d = 4$（单头简化），缓存已有 $K = \begin{bmatrix} 1 & 0 & 0 & 0 \\ 0 & 1 & 0 & 0 \end{bmatrix}$，$V = \begin{bmatrix} 2 & 0 & 1 & 0 \\ 0 & 3 & 0 & 1 \end{bmatrix}$；新 token 算得 $q_3 = [1, 1, 0, 0]$，$k_3 = [0, 0, 1, 0]$，$v_3 = [1, 1, 1, 1]$。

打分：$q_3 \cdot k_1 = 1$，$q_3 \cdot k_2 = 1$，$q_3 \cdot k_3 = 0$；除以 $\sqrt{4} = 2$ 得 $[0.5,\; 0.5,\; 0]$。

softmax：$e^{0.5} \approx 1.6487$（两项），$e^0 = 1$，和 $\approx 4.2974$，权重 $\approx [0.3837,\; 0.3837,\; 0.2327]$（和为 1 ✓）。

输出 $= 0.3837\,v_1 + 0.3837\,v_2 + 0.2327\,v_3$：

```math
\begin{aligned}
&[0.3837 \times 2 + 0.2327 \times 1,\;\; 0.3837 \times 3 + 0.2327 \times 1, \\
&\;\; 0.3837 \times 1 + 0.2327 \times 1,\;\; 0.3837 \times 1 + 0.2327 \times 1] \\
&\approx [1.00,\;\; 1.38,\;\; 0.62,\;\; 0.62]
\end{aligned}
```

**一致性验证（严格）：** 若把 $[x_1, x_2, x_3]$ 完整重算一遍，第 3 个位置的 $q_3$ 与 $K_{1..3}$、$V_{1..3}$ 同上分毫不差——$k_1, v_1, k_2, v_2$ 是各自 token 的投影，与 $x_3$ 无关（第 2 节归纳结论）；因果 mask 下位置 3 的输出只依赖这三组量。故两种方式输出逐位相同，缓存无损。

## 5. 工程视角：decode 为什么是 memory-bound

**直觉。** 有了 KV Cache，每步的算量很小（$40d^2$ 量级），但每步都要把**全部模型权重**和**整个 KV Cache** 从显存搬到计算单元——时间主要花在"搬数据"而不是"算数"上。

**工程实践的描述（非严格定理）：** prefill 是 compute-bound（大矩阵乘吃满算力，batch 越大越划算）；decode 是 memory-bound（算量小、访存大，batch 对延迟的改善有限）。"decode 瓶颈在显存带宽"是工程界的共识性描述，成立条件是常规的访存/算力配比；量化、FlashAttention 等优化改变的是常数，不改变两阶段的定性划分。

**一句话展望（需实验验证的领域）：** 缓存随 $T$ 线性增长，装不下时"丢谁"就是学问——StreamingLLM（保留注意力汇点）、H2O（保留高频 token）等驱逐策略各有实验报告，但"哪种最好"是任务相关的实验结论，本篇不展开。

## 6. 常见误区

**误区 1：KV Cache 是近似，会改变生成结果。**

纠正：不是近似。第 2 节的归纳论证给出**逐位一致**的严格保证——它是 memoization（把算过的存起来复用），数学上等价于重算。成立条件：因果 mask + 推理时无随机性。凡是"缓存导致结果漂移"的说法，都是把它和稀疏注意力等近似方法搞混了。

**误区 2：KV Cache 省内存。**

纠正：恰恰相反——它**花内存省计算**。缓存大小 $2NTd$ 随序列长度线性增长，长上下文推理中 KV Cache 经常超过模型权重本身，成为显存第一大户。觉得"缓存=省"是把"省计算"误读成了"省一切"。

**误区 3：把 Q 也缓存起来能更快。**

纠正：没有意义。每步只有一个新的 $q_t$，旧的 $q$ 在后续步骤里永远用不上——缓存它们只占内存、零复用。KV Cache 只存 K、V 是结构决定的，不是实现偷懒。

**误区 4：KV Cache 能加速训练。**

纠正：不能。训练时目标序列完整已知，一次前向算出所有位置（第 04 篇），根本不存在"重复算前缀"的问题——KV Cache 优化掉的浪费在训练流程里就不存在。它是纯粹的**推理**优化。

**误区 5：用了 KV Cache，每步计算量就和序列长度无关了。**

纠正：不完全。投影和 FFN 的 $O(t \cdot d^2)$ 被砍成了 $O(d^2)$，但注意力部分仍是 $O(t \cdot d)$——$q_t$ 每次都要和全部 $t$ 个 cached K 打分。只是 $d \gg T$ 时 $d^2$ 项是绝对大头，所以"近似无关"的直觉在常规配置下成立，$T$ 很大时（超长上下文）attention 的 $O(t \cdot d)$ 会重新成为瓶颈。

## 7. 自测题

**Q1.** 用第 2 节的归纳思路证明：在因果 mask 下，第 $t$ 步重算前缀时 $K_i^{(l)}$（$i < t$）与第 $i$ 步算出的逐位一致。指出证明中哪一步用到了因果 mask。

<details>
<summary>答案</summary>

对层数 $l$ 归纳。$l = 0$ 时 $h_i^{(0)}$ 只与 token $i$ 有关，与步数无关。因果 mask 保证 $h_i^{(l)}$ 只依赖 $\{h_j^{(l-1)} : j \le i\}$（**这一步用了因果 mask**：若无 mask，$h_i^{(l)}$ 会依赖 $j > i$ 的位置，而那些位置的表示在第 $i$ 步时还不存在、到第 $t$ 步才确定，归纳断裂）。归纳假设下所有依赖项在第 $t$ 步与第 $i$ 步相同，故 $h_i^{(l)}$ 不变，$K_i^{(l)} = h_i^{(l)}W_K^{(l)}$ 也不变。
</details>

**Q2.** 取 $N = 32$、$d = 4096$、$T = 2048$，fp16 精度：KV Cache 占多少显存？若换成 int8 量化缓存，能省多少？

<details>
<summary>答案</summary>

元素数 $= 2 \times 32 \times 2048 \times 4096 = 536{,}870{,}912$；fp16 每元素 2 字节 $\approx 1.07$ GB。int8 每元素 1 字节 $\approx 0.54$ GB，省一半（成立条件：量化本身不改变元素个数；"量化后精度损失可接受"是需实验验证的结论）。
</details>

**Q3.** 取 $d = 4096$、$T = 100$，用第 4 节公式估算 decode 阶段 KV Cache 的加速比，并说明 $T$ 继续增大到接近 $d$ 时会发生什么。

<details>
<summary>答案</summary>

$d \gg T$ 时 $d^2$ 项主导，加速比 $\approx \frac{20T^2d^2}{32Td^2} = \frac{5T}{8} = 62.5$，约 60 倍。$T$ 接近 $d$ 时，无缓存公式里的 $\frac{4}{3}T^3d$ 项（注意力 $O(t^2d)$ 累积）不再可忽略，加速比会被这项拖累而低于 $\frac{5T}{8}$——"60 倍"成立的条件是 $d \gg T$。
</details>

**Q4.** 一句话各自回答：(a) 为什么 Q 不进 KV Cache？(b) 训练时为什么不需要 KV Cache？(c) 交叉注意力的 K、V 为什么是"永不追加"的缓存？

<details>
<summary>答案</summary>

(a) 每步只有一个新 $q_t$，旧 $q$ 后续永不再用，缓存零复用。(b) 训练一次前向算出所有位置，不存在重复算前缀的浪费。(c) 交叉注意力的 K、V 来自 Encoder 输出 $Z$，生成全程不变（第 07 篇），prefill 一次、decode 纯复用。
</details>
